# Qwen3.8-27B UD-IQ3_S: Ollama + OpenCode на GPU 16 ГБ

Инструкция для **NVIDIA Quadro RTX 5000 16 ГБ**. Основной профиль: **65 536 токенов, KV-кэш Q8, один параллельный запрос**. Модель используется для текста и работы с кодом.

**Статус:** инструкция составлена по документации и проверена на согласованность конфигураций 19 октября 2026 года. Запуск на реальной RTX 5000 и качество ответов не тестировались. Приведённый расход VRAM — расчёт; полное размещение на GPU нужно подтвердить на своей машине.

## Что скачивать

| Параметр | Значение |
|---|---|
| Исходная модель | [Qwen/Qwen3.8-27B](https://huggingface.co/Qwen/Qwen3.8-27B) |
| Автор квантизации | [Unsloth](https://huggingface.co/unsloth/Qwen3.8-27B-GGUF) |
| Файл | [Qwen3.8-27B-UD-IQ3_S.gguf](https://huggingface.co/unsloth/Qwen3.8-27B-GGUF/blob/main/Qwen3.8-27B-UD-IQ3_S.gguf) |
| Размер файла | Около 12 GB, то есть 11,2 GiB |
| Имя в Ollama | `qwen38-64k:latest` |

`UD-IQ3_S` — квантизация весов. `q8_0` — отдельная настройка кэша контекста. Это разные виды сжатия. Сборка Unsloth отличается от сборок bartowski: одинаковые обозначения квантизации у разных авторов не гарантируют одинаковый размер и качество.

В этой инструкции не подключаются vision-проектор и дополнительная модель для спекулятивного декодирования. MTP отключён параметром `draft_num_predict 0`. Их подключение потребует отдельного расчёта памяти.

## 1. Подготовка

Нужны установленный драйвер NVIDIA, актуальные [Ollama](https://ollama.com/download) и [OpenCode](https://opencode.ai/docs/). Проверьте:

```text
nvidia-smi
ollama --version
opencode --version
```

`nvidia-smi` должен видеть нужную карту. Закройте приложения, занимающие её VRAM. Предусмотрите около 30 GB свободного места на диске: исходный GGUF, импортированная копия и временные файлы. Оперативная память также нужна для загрузки и работы программы.

Получите файлы инструкции через **Code → Download ZIP** на GitHub или клонируйте репозиторий:

```bash
git clone https://github.com/IlnurNig/Qwen3.8-27B_ollama_manual.git
cd Qwen3.8-27B_ollama_manual
```

Далее команды загрузки и импорта выполняются из этой папки.

## 2. Загрузка модели

### Linux / Bash

```bash
mkdir -p models
curl -fL --retry 3 -C - -o models/Qwen3.8-27B-UD-IQ3_S.gguf https://huggingface.co/unsloth/Qwen3.8-27B-GGUF/resolve/main/Qwen3.8-27B-UD-IQ3_S.gguf
sha256sum models/Qwen3.8-27B-UD-IQ3_S.gguf
```

### Windows / PowerShell

```powershell
New-Item -ItemType Directory -Force models | Out-Null
curl.exe -fL --retry 3 -C - -o models/Qwen3.8-27B-UD-IQ3_S.gguf https://huggingface.co/unsloth/Qwen3.8-27B-GGUF/resolve/main/Qwen3.8-27B-UD-IQ3_S.gguf
Get-FileHash .\models\Qwen3.8-27B-UD-IQ3_S.gguf -Algorithm SHA256
```

SHA256, опубликованный для файла на дату подготовки инструкции:

```text
d847e2c1e4aa276e4b7b8e9ad7628050e61e165d49ab995407bc36677a6f3864
```

При несовпадении проверьте актуальный хеш на странице файла: автор мог обновить сборку. Не импортируйте незавершённую загрузку. Вместо команды можно скачать файл браузером и положить его в `models/`. Веса исключены из Git через `.gitignore`.

## 3. Настройка сервера Ollama

Для основного профиля задайте **окружению сервера**, а не только клиенту `ollama run`:

| Переменная | Значение | Назначение |
|---|---|---|
| `OLLAMA_FLASH_ATTENTION` | `1` | Запросить Flash Attention |
| `OLLAMA_KV_CACHE_TYPE` | `q8_0` | Хранить KV-кэш в 8-битном формате |
| `OLLAMA_NUM_PARALLEL` | `1` | Один одновременно обрабатываемый запрос |
| `OLLAMA_MAX_LOADED_MODELS` | `1` | Одна загруженная модель |

Flash Attention уменьшает временные затраты памяти при вычислении внимания; его доступность зависит от бэкенда и GPU. В Ollama квантованный KV-кэш требует Flash Attention. Заданные переменные сами по себе не доказывают, что нужный режим действительно включился — ниже есть проверка логов.

### Linux: Ollama как служба systemd

```bash
sudo systemctl edit ollama.service
```

Добавьте в override, сохранив другие необходимые настройки службы:

```ini
[Service]
Environment="OLLAMA_FLASH_ATTENTION=1"
Environment="OLLAMA_KV_CACHE_TYPE=q8_0"
Environment="OLLAMA_NUM_PARALLEL=1"
Environment="OLLAMA_MAX_LOADED_MODELS=1"
```

Примените:

```bash
sudo systemctl daemon-reload
sudo systemctl restart ollama.service
systemctl status ollama.service --no-pager
```

Если службы нет и вы запускаете сервер вручную, используйте этот вариант **вместо systemd**:

```bash
OLLAMA_FLASH_ATTENTION=1 OLLAMA_KV_CACHE_TYPE=q8_0 OLLAMA_NUM_PARALLEL=1 OLLAMA_MAX_LOADED_MODELS=1 ollama serve
```

Оставьте терминал сервера открытым. Не запускайте второй сервер на уже занятом порту 11434.

### Windows: приложение Ollama

1. Полностью завершите Ollama через значок в системном трее.
2. В PowerShell сохраните переменные пользователя:

```powershell
[Environment]::SetEnvironmentVariable("OLLAMA_FLASH_ATTENTION", "1", "User")
[Environment]::SetEnvironmentVariable("OLLAMA_KV_CACHE_TYPE", "q8_0", "User")
[Environment]::SetEnvironmentVariable("OLLAMA_NUM_PARALLEL", "1", "User")
[Environment]::SetEnvironmentVariable("OLLAMA_MAX_LOADED_MODELS", "1", "User")
```

3. Запустите Ollama заново через меню «Пуск» и откройте новый терминал для последующих команд.

Если Ollama установлена отдельной службой Windows, задайте переменные окружению этой службы и перезапустите её: переменные текущего пользователя могут на неё не действовать.

## 4. Импорт и первый запуск

В репозитории уже есть [Modelfile](Modelfile). Основные параметры:

```dockerfile
FROM ./models/Qwen3.8-27B-UD-IQ3_S.gguf
RENDERER qwen3.8
PARSER qwen3.5
PARAMETER num_ctx 65536
PARAMETER num_batch 128
PARAMETER num_predict 8192
PARAMETER draft_num_predict 0
```

Полный файл также содержит параметры семплирования, рекомендованные Qwen для thinking-режима. `num_batch 128` — консервативная стартовая настройка расхода памяти, а не оптимизация по измеренной скорости. `num_predict 8192` ограничивает длину генерации; на сложном рассуждении лимит может закончиться до финального ответа.

Связка `RENDERER qwen3.8` и `PARSER qwen3.5` приведена [участником команды Ollama](https://github.com/ollama/ollama/issues/18297) для импорта Qwen3.8 GGUF. Она задаёт оформление диалога и разбор ответа. Если установленная версия не понимает эти директивы, обновите Ollama.

```text
ollama create qwen38-64k -f Modelfile
ollama show qwen38-64k --modelfile
ollama run qwen38-64k
```

Отправьте короткий запрос. После ответа выйдите из чата командой `/bye`.

## 5. Проверка полного размещения на GPU

После загрузки модели выполните:

```text
ollama ps
nvidia-smi
```

У `qwen38-64k:latest` нужны **`PROCESSOR = 100% GPU`** и **`CONTEXT = 65536`**. Это ожидаемые значения, а не сохранённый результат теста.

`CPU/GPU` в столбце `PROCESSOR` означает частичное размещение в оперативной памяти. Высокая загрузка GPU сама по себе не подтверждает, что все слои находятся в VRAM.

Проверьте логи сервера после загрузки модели:

```bash
# Linux / systemd
journalctl -u ollama.service -n 200 --no-pager
```

```powershell
# Windows / стандартное приложение
Get-Content "$env:LOCALAPPDATA\Ollama\server.log" -Tail 200
```

Ищите сведения об используемом GPU, размещении слоёв, Flash Attention и типе K/V-кэша. Названия полей зависят от версии. Важно увидеть фактический режим загрузки, а не только список переменных окружения. При недостатке подробностей временно задайте `OLLAMA_DEBUG=1` серверу, перезапустите и повторите загрузку.

Повторите проверку во время реальной длинной сессии OpenCode. Если кэш остался F16, приведённый ниже расчёт для Q8 неприменим.

## 6. Проверка вызова инструмента

Обычный текстовый ответ ещё не подтверждает работоспособность tool calling. В [examples/tool-call.json](examples/tool-call.json) есть небольшой запрос с функцией `add_numbers`.

Linux:

```bash
curl -fsS http://127.0.0.1:11434/api/chat -H 'Content-Type: application/json' --data-binary @examples/tool-call.json
```

Windows / PowerShell:

```powershell
curl.exe -fsS http://127.0.0.1:11434/api/chat -H "Content-Type: application/json" --data-binary "@examples/tool-call.json"
```

Ожидается элемент в `message.tool_calls` с именем `add_numbers` и аргументами `a: 17`, `b: 25`. Это проверка формата вызова: функция на компьютере не исполняется. Если модель пишет текст вместо структурированного вызова, проверьте renderer/parser и версию Ollama. Thinking в этом коротком тесте отключён только на уровне запроса.

## 7. Подключение OpenCode

Возьмите [opencode.64k.example.json](opencode.64k.example.json). Сохраните его как `opencode.json` **в корне проекта, с которым будете работать**. Если конфигурация уже существует, объедините блок `provider.ollama` и настройку `model` с ней, сохранив остальные настройки.

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "ollama/qwen38-64k:latest",
  "provider": {
    "ollama": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Ollama local",
      "options": {
        "baseURL": "http://127.0.0.1:11434/v1"
      },
      "models": {
        "qwen38-64k:latest": {
          "name": "Qwen3.8 27B UD-IQ3_S 64k",
          "tool_call": true,
          "reasoning": true,
          "limit": { "context": 65536, "output": 8192 }
        }
      }
    }
  }
}
```

Запустите `opencode` из папки проекта. Через `/models` проверьте выбранную модель. Сначала попросите прочитать один файл и объяснить его назначение, чтобы проверить настоящий цикл работы инструментов.

`num_ctx` задаёт окно в Ollama. `limit.context` сообщает доступное окно OpenCode. Увеличение только второго параметра не увеличивает контекст сервера. Число 65 536 включает инструкции, историю, код, результаты инструментов и ответ; запас на генерацию и служебные сообщения уменьшает объём доступного входного текста.

Альтернатива ручной настройке — `ollama launch opencode`, но при использовании собственной конфигурации запускайте `opencode` напрямую: launcher может передать свою конфигурацию выбранной модели.

## 8. Сколько нужно видеопамяти

Ниже **плановая оценка**, а не результат профилирования. Предположения: один запрос, текст, без MTP, весовой файл около 12 GB, работающий Flash Attention и выбранная точность кэша.

| Профиль | Веса | KV-кэш | Заложенный запас на состояния/буферы | Ориентир всего |
|---|---:|---:|---:|---:|
| 65 536 + Q8 | ≈11,2 GiB | ≈2,13 GiB | 1–2 GiB | ≈14,3–15,3 GiB |
| 65 536 + F16 | ≈11,2 GiB | ≈4,00 GiB | 1–2 GiB | ≈16,2–17,2 GiB |
| 120 000 + Q8 | ≈11,2 GiB | ≈3,89 GiB | 1–2 GiB | ≈16,1–17,1 GiB |
| 120 000 + Q4 | ≈11,2 GiB | ≈2,06 GiB | 1–2 GiB | ≈14,2–15,2 GiB |

Выделение памяти конкретным бэкендом, выравнивание и буферы могут изменить результат. Занятая другими программами VRAM дополнительно уменьшает доступный объём. Для двух параллельных запросов таблица не подходит.

Основа расчёта KV: в [конфигурации модели](https://huggingface.co/Qwen/Qwen3.8-27B/blob/main/config.json) 16 слоёв полного внимания, 4 KV-головы, размер головы 256. Для F16 объём равен `токены × 16 × 4 × 256 × 2 (K и V) × 2 байта`. Q8_0 занимает примерно 34 байта на 32 значения, Q4_0 — 18 байт. Состояния линейного внимания учитываются отдельно в запасе, а не в этой формуле.

GB и GiB — разные единицы: `1 GiB = 2^30 байт`. Размер файла на Hugging Face не равен полному расходу видеопамяти при работе.

## 9. Экспериментальный профиль 120 000 токенов

Само окно находится в пределах возможностей исходной модели. На 16 ГБ вариант **120k + Q8** не стоит считать помещающимся целиком на GPU. Для эксперимента используйте **120k + Q4-кэш**, принимая возможные потери точности на длинном контексте.

1. Сначала создайте основной `qwen38-64k` по инструкции выше.
2. Поменяйте окружение сервера на `OLLAMA_KV_CACHE_TYPE=q4_0`, оставив остальные переменные без изменений, и перезапустите сервер.
3. Создайте второй профиль:

```text
ollama create qwen38-120k -f Modelfile.120k
ollama run qwen38-120k
```

4. После первого ответа выполните `ollama ps`: нужны `100% GPU` и `120000`.
5. Для OpenCode используйте [opencode.120k.example.json](opencode.120k.example.json).

**Точность KV-кэша — глобальная настройка сервера.** Переключение имени модели с `qwen38-120k` обратно на `qwen38-64k` само по себе не вернёт Q8. Для возврата задайте `OLLAMA_KV_CACHE_TYPE=q8_0`, перезапустите Ollama и выберите профиль 64k.

Q4 экономит память сильнее Q8, но Ollama предупреждает о более заметных потерях точности, особенно на длинном контексте. Для исправления кода основной рекомендуемый профиль здесь — **64k + Q8**. Длинный контекст также увеличивает объём обработки запроса; скорость на RTX 5000 не измерялась.

## 10. Частые проблемы

| Симптом | Что проверить |
|---|---|
| `address already in use` | Уже запущен сервер на 11434. Используйте его после настройки окружения либо корректно остановите перед ручным запуском. |
| Ошибка `RENDERER` или `PARSER` | Обновите Ollama; затем заново выполните `ollama create`. |
| Модель загрузилась частично на CPU | Убедитесь в Q8-кэше для 64k, одном запросе и свободной VRAM. Если всё равно не помещается, потребуется меньший контекст или более компактная квантизация. |
| Ошибка CUDA / out of memory | Освободите VRAM, проверьте фактический тип кэша и уменьшите контекст. Не считайте теоретическую таблицу гарантией. |
| В логе нет Flash Attention / квантованный кэш недоступен | Проверьте версию, драйвер и выбранный бэкенд. При F16 заново оцените память; не рассчитывайте на размеры Q8/Q4. |
| В OpenCode появляется текст `<tool_call>` вместо действия | Проверьте тест из раздела 6, renderer/parser, имя модели и настройку провайдера. |
| Ответ обрывается или всё уходит на рассуждение | Проверьте лимит генерации 8192. Для сложных задач его можно поднять вместе с `limit.output`, сохранив запас внутри общего окна. |
| OpenCode считает, что доступно другое окно | Проверьте выбранный профиль, `num_ctx`, `limit.context` и возможную конфигурацию, переданную launcher. |

## 11. Что означают настройки

- **KV-кэш** хранит промежуточные данные внимания для уже обработанных токенов. Его квантизация меняет точность этих данных; текст не сокращается автоматически.
- **Flash Attention** экономнее вычисляет внимание и может ускорять обработку длинного запроса. Сам по себе он не переводит веса или кэш в Q8.
- **Полностью на GPU** здесь означает размещение слоёв и кэша на видеокарте. CPU всё равно обслуживает программу, токенизацию и инструменты OpenCode; системная RAM также используется.
- **Размер окна** — вместимость одного диалога. Он не гарантирует одинаковую точность извлечения деталей во всех его частях.
